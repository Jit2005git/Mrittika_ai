# 🌱 Mrittika AI

> **From Soil & Weather Data to Smarter Crop Decisions.**

Mrittika AI is an AI-powered agricultural decision-support platform designed to help farmers and agricultural users make more informed crop decisions by combining **soil parameters, geographic location, live weather information, machine learning, and conversational AI** into a single platform. Instead of presenting agricultural information as disconnected data points, Mrittika transforms soil, weather, and location data into an actionable crop recommendation and provides an AI agricultural assistant that can answer questions and explain recommendations. The core problem addressed by Mrittika is that farmers often have access to agricultural information from different sources, but connecting soil conditions, weather, crop suitability, and agricultural advice into one practical decision can be difficult. Mrittika addresses this problem through a simple **Data → Decision → Explanation** workflow. The platform allows users to create an account, securely log in, provide soil parameters, detect or provide geographic location, retrieve weather information, run machine-learning-based crop prediction, view recommended crops, and interact with an AI agricultural assistant. The primary target users are farmers, small and medium-scale growers, agricultural students, agricultural support workers, and users seeking crop suitability guidance. Mrittika combines three major layers: a data layer that collects Nitrogen, Phosphorus, Potassium, soil pH, temperature, humidity, rainfall, latitude, longitude, and weather information; an intelligence layer that uses machine learning, soil information, location, and weather conditions to generate crop recommendations; and a conversational AI layer that provides agricultural guidance and explanations. Key features include **user authentication, JWT-based authentication, weather integration, manual crop prediction, smart crop prediction, geographic location support, AI agricultural assistance, language preference support, and frontend-backend integration**. In the smart crop prediction workflow, the system combines soil parameters, geographic location, and live weather information before generating a crop recommendation. For example, a prediction may return results such as Rice → 40%, Maize → 23%, and Coffee → 20%, depending on the provided inputs and trained model. Mrittika is different from a conventional agricultural dashboard because its primary goal is not simply to display information but to transform information into an actionable decision and then provide an explanation. The core concept is **Soil + Weather + Location → Machine Learning → Crop Recommendation → AI Explanation**. The system architecture consists of a React/Vite frontend connected to a FastAPI backend and an n8n-based AI workflow. The FastAPI backend handles authentication, weather services, crop prediction, smart crop prediction, and database operations, while the n8n workflow handles the conversational AI assistant using components such as Gemini, AI Agent, conversation memory, embeddings, and vector storage. The overall architecture can be represented as **React/Vite → FastAPI → Authentication / Weather / ML → Crop Recommendation**, while the AI assistant follows **React → n8n Chat Trigger → AI Agent → Gemini + Memory + Vector Store → Agricultural Response**. The standard crop prediction workflow is **User → Login → Crop Prediction Page → Enter Soil Parameters → FastAPI Backend → ML Model → Crop Prediction → Frontend Result**. The smart prediction workflow is **User → Detect/Enter Location → Enter N/P/K/pH → FastAPI → Weather Service → Combine Soil + Weather + Location → ML Prediction → Crop Recommendation → Frontend**. The AI assistant workflow is **User → Mrittika AI Assistant → n8n Chat Trigger → AI Agent → Gemini / Memory / Vector Store → Agricultural Response → User**. The technology stack includes **React.js, Vite, JavaScript, Axios, CSS, Python, FastAPI, Uvicorn, Pydantic, JWT authentication, Scikit-learn, n8n, Gemini, AI Agent, Simple Memory, Embeddings, Vector Store, PostgreSQL, SQLite, Git, GitHub, VS Code, and AI-assisted development tools**. The project structure is organized as `Mrittika_ai/` containing `Mrittika-Backend/`, `frontend/`, `docs/`, and `README.md`. The backend contains the FastAPI application, configuration, database layer, models, schemas, routers, services, `main.py`, `requirements.txt`, and environment configuration, while the frontend contains React components, context, pages, services, public assets, `package.json`, Vite configuration, and environment configuration. To run the project locally, Python 3.12+, Node.js 18+, npm, Git, a database configuration, and an n8n workflow are recommended. Clone the repository using `git clone https://github.com/Jit2005git/Mrittika_ai.git` and enter the project directory using `cd Mrittika_ai`. For the backend, navigate to `Mrittika-Backend`, create a virtual environment using `python -m venv venv`, activate it using `.\venv\Scripts\Activate.ps1`, and install dependencies using `pip install -r requirements.txt`. The backend environment file should contain values such as `DATABASE_URL`, `SECRET_KEY`, and `WEATHER_API_KEY`. For the frontend, navigate to `frontend`, run `npm install`, and configure the `.env` file with `VITE_API_BASE_URL=http://127.0.0.1:8001` and `VITE_N8N_CHAT_URL=your_n8n_chat_url`. The backend can be started using `python -m uvicorn main:app --reload --host 127.0.0.1 --port 8001`, after which the backend is available at `http://127.0.0.1:8001`, the interactive FastAPI Swagger documentation is available at `http://127.0.0.1:8001/docs`, and the health endpoint is available at `http://127.0.0.1:8001/health`. The frontend can be started from the `frontend` directory using `npm run dev`, normally making the application available at `http://localhost:5173`. The backend API uses the `/api/v1` prefix and includes authentication endpoints such as `POST /api/v1/auth/signup`, `POST /api/v1/auth/login`, `GET /api/v1/auth/me`, and `PATCH /api/v1/auth/language`. Crop prediction is available through `POST /api/v1/crop-predict`, while smart crop prediction is available through `POST /api/v1/smart-crop-predict`. Weather services include `GET /api/v1/weather/weather` and `GET /api/v1/weather/current`. A typical crop prediction request contains `N`, `P`, `K`, `temperature`, `humidity`, `ph`, and `rainfall`, while a smart crop prediction request can contain `N`, `P`, `K`, `ph`, `latitude`, and `longitude`. The smart prediction system can then retrieve weather information and combine environmental context with soil information before generating the recommendation. The AI agricultural assistant is connected through an n8n workflow containing a chat trigger, AI Agent, Gemini Chat Model, Simple Memory, and Vector Store with embeddings. The frontend can connect to the hosted n8n chat through the `VITE_N8N_CHAT_URL` environment variable. Sensitive credentials such as Gemini API keys, n8n credentials, database passwords, JWT secrets, and private API keys must never be exposed in frontend code or committed to GitHub. One of the most important planned enhancements is **context-aware AI explanation**, where the actual prediction context — including soil values, location, weather conditions, recommended crop, and potentially model confidence — is passed to the AI assistant. This would allow a user to ask **“Why did you recommend rice?”** and receive an explanation based on the actual prediction instead of a generic agricultural response. The machine-learning layer processes agricultural features such as Nitrogen, Phosphorus, Potassium, temperature, humidity, pH, and rainfall through a trained crop recommendation model. The conceptual ML pipeline is **Input → Validation → Feature Preparation → ML Model → Prediction → Recommendation**. The database layer supports PostgreSQL for production environments and SQLite as a local development fallback, with application data such as users, authentication-related information, preferences, and language settings being stored through the backend database layer. The frontend is built using React and Vite and communicates with the FastAPI backend through Axios, with the API base URL configured through `VITE_API_BASE_URL`. Security considerations include JWT authentication, environment-based secret management, CORS configuration, input validation, HTTPS for production, restricted CORS origins, production database configuration, API-key rotation, rate limiting, and protection of sensitive endpoints. Important integration tests include frontend availability, backend health, user signup, login, JWT authentication, current user retrieval, language preference, weather API, current weather, manual crop prediction, smart crop prediction, and CORS. The frontend production build can be verified using `npm run build`. FastAPI Swagger at `/docs` provides an interactive interface for viewing endpoints, testing APIs, inspecting request schemas, and debugging backend functionality. The recommended Git branching strategy consists of `main`, `integration`, `frontend`, and `testing`, where `main` contains the stable submission/deployment version, `integration` combines major project components, `frontend` is used for frontend development, and `testing` is used for testing and bug fixing. A typical Git workflow includes `git pull origin integration`, switching to the appropriate branch, checking changes using `git status`, staging with `git add .`, committing with a descriptive message such as `git commit -m "feat: update frontend integration"`, and pushing using `git push origin frontend`. For the hackathon demonstration, the recommended flow is **Login → Dashboard → Crop Prediction → Enter Soil Data → Detect Location → Retrieve Weather → Smart Crop Prediction → Show Recommended Crop → Open AI Assistant → Ask “Why did you recommend this crop?” → Explain the ML + AI architecture**. The core hackathon pitch is that farmers have access to agricultural information, but it is often fragmented across soil analysis, weather platforms, crop information, and advisory systems. Mrittika combines soil, weather, location, machine learning, and generative AI to provide a more actionable agricultural decision-support experience. The one-line pitch is: **“Mrittika turns soil, weather and location data into smarter crop decisions — and AI helps explain why.”** The current MVP focuses on **authentication, React frontend, FastAPI backend, weather integration, soil input, ML crop prediction, smart crop prediction, location context, n8n AI assistant, frontend-backend integration, and basic agricultural AI assistance**. Mrittika is currently a decision-support prototype and has limitations: ML predictions depend on training data, model quality, input quality, and environmental variability; weather information may contain forecast uncertainty, API delays, missing information, or geographic limitations; and generative AI may occasionally provide incorrect or incomplete information. Therefore, recommendations should be treated as advisory information rather than guaranteed agricultural outcomes. Future development can include explainable AI, crop disease detection using computer vision, multilingual voice assistance, personalized farm profiles, crop calendars, market intelligence, disease and pest alerts, satellite imagery, NDVI, GIS, remote sensing, and field-level monitoring. Future production deployment can use a cloud architecture consisting of a CDN, React frontend, API gateway, FastAPI services, ML service, weather service, authentication service, recommendation engine, and PostgreSQL database, with AI services connected through n8n or dedicated AI infrastructure. Potential success metrics include model accuracy, API latency, prediction latency, chat response time, system uptime, recommendation usefulness, user engagement, AI assistant usage, crop suitability, disease detection accuracy, recommendation acceptance, and long-term agricultural outcomes. Mrittika follows three design principles: **Simple, Actionable, and Explainable**. The user should not need technical knowledge, the system should answer what the user can consider doing rather than merely displaying data, and users should be able to ask “Why?” and receive a meaningful explanation. Mrittika is being developed as a collaborative hackathon project with responsibilities covering backend and integration, frontend development, AI and automation, testing, and deployment.
